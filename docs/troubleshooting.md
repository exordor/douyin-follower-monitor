# Troubleshooting

这份文档面向开源使用场景，优先给出可操作的排查步骤。请只使用你有权访问的账号和本机浏览器登录态，并遵守平台规则。

项目能力边界：

- 不自动识别、滑动或绕过验证码。
- 不绕过登录、风控、签名或隐私限制。
- 不提供代理池、账号池或批量规避方案。
- 不恢复、补全或反查隐藏粉丝。
- 不在 issue、日志或截图里暴露真实账号标识、真实 secUid、cookie 值或具体 cookie 名称；如需描述，请使用 `session cookie` 这类泛化说法。

## 触发验证码怎么办

### 现象

采集启动后浏览器出现验证码、中间页或登录验证页；dashboard 中 `phase` 可能显示为 `waiting_for_verification`，并带有等待倒计时。

### 原因

抖音可能因为新 profile、登录态变化、访问频率、网络环境或账号安全策略要求人工验证。项目只复用你已有的登录态，不会也不能保证免验证码。

### 处理步骤

1. 在弹出的浏览器窗口中手动完成验证码或登录验证。
2. 保持采集进程运行，等待任务继续；不要反复关闭并重启浏览器。
3. 如果默认等待时间不够，可延长人工验证窗口，例如设置 `DOUYIN_AUTH_WAIT_SECONDS=600` 后重新启动 dashboard 或采集任务。
4. 验证完成后，先跑一次轻量采集确认登录态可用，再按需要执行 full 扫描。

### 不建议做什么

- 不要使用自动打码、模拟拖动、绕过验证码的脚本或服务。
- 不要高频重试登录，这通常只会增加风控概率。
- 不要把验证码截图、账号主页、真实 secUid 或 cookie 信息贴到公开 issue。

## Cookie 导入后仍未登录

### 现象

导入 cookie-manager 无损 JSON 后，页面仍显示未登录、要求扫码登录，或者采集提示缺少登录态。

### 原因

常见原因包括：cookie 已过期；导出的不是无损 JSON；cookie 域名不匹配目标站点；导入的是 redacted 文件；浏览器里已经打开的页面没有重新导航；平台要求额外验证。

### 处理步骤

1. 确认导入文件来自 Local Cookie Manager 的无损 JSON，格式为 `local-cookie-manager-v1`。
2. 确认文件只来自你自己的登录浏览器，不要混用其他账号或设备的导出。
3. 保持原来的持久 Profile。CDP 的“打开采集浏览器”和采集入口会载入项目 Cookie 并重新导航目标页；不要通过反复新建 Profile 排查登录问题。
4. 如页面仍要求验证，请按页面提示人工完成；cookie 只能复用登录态，不能绕过平台验证。
5. 在 dashboard 的 Cookie 状态或 Runtime 健康信息里查看导入数量摘要，不要通过打印 cookie 内容排查。

### 不建议做什么

- 不要提交、粘贴或截图真实 cookie 值，也不要公开具体 cookie 名称。
- 不要导入 redacted 文件、过期文件或来源不明的 cookie。
- 不要把 cookie 当作免登录、免验证或跨账号复用方案。

## CDP 连接失败

### 现象

使用 `DOUYIN_CDP_URL` 或 `--cdp-url` 后，采集报连接失败、目标不可访问、没有可用页面，或浏览器没有响应。

### 原因

Chrome/Edge/Chromium 可能没有带 remote debugging 参数启动；端口不一致；已有同 profile 浏览器进程占用；目标浏览器被关闭；防火墙或代理阻断了本机端口。

### 处理步骤

1. 优先在电脑端设置页点击“打开采集浏览器”；本机 CDP 未启动时，项目会自动打开固定配置的专用 Chrome。需要手动启动时，保持同一目录和端口：

   ```bash
   /Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
     --remote-debugging-port=9222 \
     --user-data-dir="$HOME/BrowserProfiles/douyin-follower" \
     --profile-directory=Default
   ```

2. 打开抖音页面并确认该浏览器里已经完成登录。
3. 让采集使用同一个端口：

   ```bash
   DOUYIN_CDP_URL=http://127.0.0.1:9222 npm run monitor
   ```

4. 如果仍失败，检查端口是否被其他服务占用、专用目录是否正在被另一进程使用。先正常退出对应专用浏览器再重试；不要自动删除锁或新建空白 Profile。若确需换端口，同步更新 CDP 地址，仍保留原 Profile。

### 不建议做什么

- 不要把 CDP 端口暴露到公网或共享网络。
- 不要复用日常主浏览器 profile 做反复调试。
- 不要在连接失败时改动数据库或手工删除历史扫描结果。

## Playwright profile 首次登录

### 现象

首次运行默认 runtime 时，Playwright 打开的浏览器是未登录状态，或者需要扫码、短信、验证码等人工操作。

### 原因

默认 Playwright runtime 使用项目本地持久 profile。新 profile 没有你的日常浏览器登录态，首次使用需要建立会话。

### 处理步骤

1. 运行采集或 dashboard，让 Playwright 浏览器窗口打开。
2. 在该窗口中手动完成登录和必要验证。
3. 登录成功后不要删除 `.douyin-browser`，后续运行会继续复用这个持久 profile。
4. 如果你更希望复用已经登录的 Chrome/Edge/Chromium，可以改用 CDP runtime。

### 不建议做什么

- 不要尝试让项目绕过扫码、短信或验证码。
- 不要把 `.douyin-browser` 目录提交到仓库或分享给他人。
- 不要频繁删除 profile 后重新登录，这会增加验证成本。

## `Douyin webpack runtime is not available`

### 现象

API 采集模式报错：`Douyin webpack runtime is not available`。

### 原因

采集依赖当前抖音页面已经加载的前端运行时和页面请求逻辑。如果页面还没完全加载、停在登录/验证码/错误页、页面结构变化，或打开的不是支持的抖音 Web 页面，就可能找不到 runtime。

### 处理步骤

1. 确认浏览器当前页面是正常加载完成的抖音 Web 页面，而不是登录页、验证码页、空白页或错误页。
2. 手动刷新页面，等待内容稳定后重试采集。
3. 如果使用 CDP，确认连接的是包含抖音页面的那个浏览器实例。
4. 如果问题持续出现，可能是抖音前端结构变化；请按本文“API 结构变化时如何提 issue”提供脱敏信息。

### 不建议做什么

- 不要在登录页、验证码页或未加载完成的页面上反复运行 full 扫描。
- 不要为了绕过 runtime 检查去注入未知脚本。
- 不要贴出真实账号页面源码、真实 secUid、cookie 或请求认证信息。

## 粉丝数和可枚举列表对不上

### 现象

主页显示的粉丝数大于项目扫描到的 active 粉丝数量，或者 dashboard 里的 `hiddenOrUnavailableCount` 不为 0。

### 原因

抖音账号可以设置不在他人关注和粉丝列表中公开出现。这类账号可能计入主页粉丝数，但不会出现在可枚举粉丝分页结果中。项目只记录当前账号可枚举的粉丝列表。

### 处理步骤

1. 以 full 扫描结果作为可枚举基线。
2. 把 `hiddenOrUnavailableCount = 主页粉丝数 - 可枚举粉丝数` 理解为统计差值，不是可恢复名单。
3. 判断取关时只依赖连续 full 扫描中的可枚举结果，不用主页粉丝数直接推断具体账号。

### 不建议做什么

- 不要要求项目恢复隐藏粉丝或反查不可枚举账号。
- 不要把主页粉丝数差值当作具体取关人数。
- 不要提交含真实粉丝列表、真实账号标识或真实 secUid 的截图。

## full 扫描中断后如何处理

### 现象

full 扫描过程中断电、断网、浏览器关闭、进程退出，或者 dashboard 显示任务失败。`data/in-progress/` 里可能保留 `latest.partial.*` 文件。

### 原因

full 扫描需要完整遍历可枚举分页。中断时，部分结果只能代表当时已经扫到的进度，不能作为完整基线推进取关判断。

### 处理步骤

1. 保留数据库和 `data/` 下已有输出，不要手工清空历史状态。
2. 重新运行 full 扫描，让它生成完整的新基线。
3. 如需人工查看中断前进度，可参考 `data/in-progress/latest.partial.json` 或 `latest.partial.csv`，但不要把它当作最终扫描结果。
4. full 成功完成后，再查看 dashboard 中的扫描记录、事件和状态变化。

### 不建议做什么

- 不要把 partial 文件改名成 `latest.json` 或手工导入为最终结果。
- 不要删除 SQLite 数据库来“修复”一次中断。
- 不要用 recent 扫描替代失败的 full 扫描来判断取关。

## API 结构变化时如何提 issue

### 现象

原本可用的采集突然稳定失败，报接口字段缺失、分页异常、webpack runtime 不可用，或 full/recent 扫描结果明显不完整。

### 原因

抖音 Web 页面、前端运行时、分页接口或响应字段可能发生变化。项目是非官方工具，依赖可枚举页面能力，平台更新可能导致适配失效。

### 处理步骤

1. 先确认登录态正常、验证码已人工完成、页面可以在浏览器中正常打开。
2. 记录项目版本或 commit、Node.js 版本、操作系统、runtime 类型、运行命令、错误堆栈中与项目代码相关的部分。
3. 描述失败发生在 recent 还是 full、是否每次复现、是否只有 CDP 或 Playwright 复现。
4. 提供脱敏后的结构信息，例如字段是否缺失、分页是否提前结束、错误消息文本。必要时用占位符替换账号标识。
5. 在 issue 中说明你没有附带真实账号标识、真实 secUid、cookie 值、请求认证信息或完整个人数据导出。

### 不建议做什么

- 不要上传真实 cookie、完整 HAR、完整页面源码、真实粉丝列表或数据库文件。
- 不要公开真实账号主页、真实 secUid、手机号、二维码或私信截图。
- 不要把“希望绕过验证码、登录、签名、隐私限制”作为修复诉求；这不属于项目目标。
